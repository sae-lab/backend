# 수동 실행이 필요한 DB 변경

이 폴더의 SQL은 **자동으로 실행되지 않는다.** 각자 DB에 직접 한 번 실행해야 한다.

## 왜 필요한가

이 프로젝트는 `spring.jpa.hibernate.ddl-auto=update`로 스키마를 맞춘다.
`update`는 **없는 것을 추가만 하고, 이미 있는 것을 완화하거나 제거하지 못한다.**

- 새 테이블 / 새 컬럼 추가 → 자동으로 반영된다 (여기 적을 필요 없음)
- NOT NULL 제약 해제, 컬럼명 변경, 타입 축소, 컬럼 삭제 → **반영되지 않는다**

즉 엔티티에서 `nullable = false`를 떼도 DB의 NOT NULL은 그대로 남는다.
코드는 통과시키는데 DB가 마지막에 거부해서, 원인을 알기 어려운 500 에러가 난다.

## 실행 방법

Supabase 대시보드 → SQL Editor에 파일 내용을 붙여넣고 실행한다.

## 언제 여기에 추가하나

엔티티에서 제약을 **푸는** 방향으로 바꿨다면 여기에 SQL을 남긴다.
새 컬럼·새 테이블을 추가한 것뿐이라면 `update`가 알아서 하므로 적지 않아도 된다.

스키마 변경이 잦아지면 Flyway 같은 마이그레이션 도구를 붙이는 편이 낫다.
그때는 이 폴더를 정식 마이그레이션으로 옮기면 된다.
